Symbolic music prediction

Forecasting notated rests in Sibelius’s Le Sapin

A single-score study with a shared-target model comparison · 14 November 2026

Abstract

A written rest can interrupt a musical phrase or leave it unresolved. We ask whether language models can anticipate these rests from a score prefix when given the target’s voice and onset. In Sibelius’s Le Sapin, Humans& Ampersand v0.1 improved on forecasts based on rest frequency and metrical position. Adding pitch yielded no clear full-score improvement for Ampersand. On shared upper-voice targets, models from three providers improved on a constant forecast. These experiments establish conditional rest forecasting as a measurable ability in this score.

1. Task and relation to prior work

A composer can use a rest to interrupt a phrase, leave it unresolved, or suggest loss or yearning. In Sibelius’s Le Sapin, one voice can fall silent while the others continue, so the expressive role of a pause may depend on what surrounds it. That possibility motivated this study. If a language model can recognize where a rest fits in the unfolding score, its forecasts might eventually help readers identify moments worth examining in a musical interpretation.

Janssen, Collins and Ren’s MIREX task uses a musical excerpt as context for generating or identifying a continuation. [1] We adapted that setup to ask whether the preceding score helps a model anticipate a printed rest. Each prompt supplied the voice and onset of a withheld event so that the evaluation focused on the event type. The model returned a probability, allowing the score to reflect how confident the forecast was.

We compared Ampersand, three GPT variants and three Claude variants on the same balanced set of upper-voice targets. Five variants improved on the constant forecast under both inputs. GPT-6 Astra had the lowest observed Brier score in both. GPT-6.1 Sol nearly matched it with rhythm alone. Claude Opus 5.5 led the Claude variants in both conditions. We also tested Ampersand across all eligible events in the three-voice score, where it outperformed reference forecasts based on rest frequency and metrical position.

To examine what information helped, we removed written pitches while keeping timing, voice labels and markings fixed. Adding pitch yielded no clear improvement across the full score. At two closing rests, we also removed the preceding barline fermata to see whether the cue changed the forecast. Its effect varied across targets and input conditions. These tests measure how models respond to musical notation, a first step toward studying whether their forecasts can help interpret expressive pauses.

2. Dataset and representation

From engraved score to event table

The label source was the 1922 Wilhelm Hansen engraving edited and revised by Julia A. Burt, on Sibley PDF pages 41–43. We used Audiveris to convert the scan to MusicXML and compared it with a separately supplied MuseScore MusicXML export. When the files disagreed, the engraved symbols determined the labels. [2]

  1. Read the notation and recover timing. Unpack the compressed MusicXML and read its score in measure order. Convert each duration from divisions to quarter-note units using the current divisions value. Advance the cursor for ordinary events, retain the preceding onset for a chord member, and apply <backup> and <forward> to recover position across voices. Use exact rational values throughout. A forward move can create a gap but supplies no rest label.
  2. Reconcile symbols with the print. Exclude hidden rest elements and notes with invisible noteheads from the label candidates while retaining their effect on the XML cursor. Map notation lanes to independently moving or sustained upper, inner and bass lines. Preserve the moving voice when a beam crosses staves. Check the position and duration of each printed rest. For example, the supplied file merges each opening quarter-and-eighth-rest pair in spans 53 and 54 into one dotted rest. The transcription retains both printed symbols. It also uses the printed tuplet reading and span boundaries in the free passages.
  3. Validate and version the tables. Check every printed rest and all seven fermata locations against the score. Spot-check note pitches and durations, including reconciled notes. Check for duplicate event identities, overlaps within a voice and broken tie links. Use the score as the validation evidence. Store event-attached marks with the event and the three barline fermata locations in a separate table. Verify the hashes of both tables before assembling prompts.

A span is a numbered score segment. Most spans are 3/4 measures. The opening and the unbarred Risoluto are free spans with positions expressed as quarter-note offsets. Notes or chords beginning together in one voice form one onset. An explicitly printed rest is a separate event in its own voice, including when another voice sounds. An unnotated gap produces no event. Cross-staff figures retain their voice assignment. Tied continuations remain in the history as printed segments and contribute no new prediction target.

3. Evaluation design

Inputs and controls

For target i, use its (span, rational beat, voice) as the identifier. Sort the event history by span and beat and retain rows whose onset is strictly earlier than the target onset. This cutoff withholds every simultaneous event, including events in the other voices. A barline fermata printed before that onset may appear as a separate BOUNDARY row with voice score and blank pitch and duration. At the closing targets, the masked prompt removes that row alone. The title and composer are omitted.

The CSV record uses bar,beat,voice,type,pitch,duration,marks. The bar field carries the span ID, and type distinguishes NOTE, REST and BOUNDARY. The last line supplies the target’s voice, span and beat and asks for a single JSON probability. The opening supplies context only. Tied continuations retain their written segment durations in the prefix so the prompt does not expose the length of a later continuation.

Pitch
Written note name, accidental and octave, such as F♯4. A chord lists the pitches that begin together in one voice. Rest rows have no pitch.
Rhythm
Written onset and duration in quarter-note units. Beat 1 is the start of a span. A duration of ½ is an eighth note or rest. The rhythm-only prompt also retains the key signature, voice labels, earlier note/rest labels and score markings.
Voice and target
A voice is a notated musical line. The target is one withheld event at a supplied voice, span and beat.
Fermata and ablation
A fermata marks a hold or pause. Here the cue is at the barline. An ablation removes a specified input field or cue and measures how forecasts change.
Baseline and Brier score
A baseline is a reference forecasting rule. Brier score measures squared probability error on a scale from 0 to 1, with lower values indicating better forecasts.

The pitch-plus-rhythm and rhythm-only prompts differ by the removal of pitch values. Both retain the key signature, rhythm, voice labels and available markings. For spans 53 and 55, an additional prompt removes only the immediately preceding boundary fermata. These marks precede the quarter rest in span 53 and the whole-measure rest in span 55.

For the full-score experiment, Ampersand v0.1 made three independent forecasts per target and condition in shuffled order. The 3,696 production requests comprise 3,684 main forecasts and 12 masked-cue forecasts.

Scoring and uncertainty

If yi is 1 for a rest and 0 for a note or chord, and pir is the forecast in valid repeat r, each target contributes the mean of its squared probability errors. The reported Brier score averages those target losses. [3]

Brier = (1 / N) ∑i (1 / Ri) ∑r (pir − yi)²

References include a constant 0.5 probability, the rest prevalence outside the target span, and two metered-only rules based on beat position and the preceding span. The beat-position rule is voice-specific and uses Beta(1,1) smoothing. The previous-span rule checks for a same-voice event at the same beat and returns 0.9 for a rest, 0.1 for a note or chord and 0.5 if the reference event is unavailable. A descriptive balanced panel contains 12 rests and 12 unique same-voice notes matched by beat, previous event type and distance to a barline.

Because notes and chords outnumber rests in the full score, we report class-specific recall and distinguish the metered and free passages. The pitch effect subtracts pitch-plus-rhythm loss from rhythm-only loss on common valid repeat indices. Positive values favor adding pitch. The whole-score and metered intervals use 10,000 resamples of consecutive four-span blocks. The intervals characterize sensitivity within the piece, whose targets share much of their context. The two fermata cases are summarized individually.

Class-specific performance

At a threshold of 0.5 on each target’s mean forecast, accuracy was 559/614 with pitch and 560/614 without pitch. Rest recall was 73/109 and 72/109, while note or chord recall was 486/505 and 488/505. An always-note classifier gives 505/614 correct. Scoring the mean probability across repeats gave ensemble Brier scores of 0.07020 and 0.06835. Exploratory ROC-AUC was 0.923 and 0.924.

Interpreting Figure 2

Each target contributes one value, the mean of its valid forecasts. We group these values into ten bins, each spanning ten percentage points. The horizontal coordinate of each point is the mean forecast within its bin. The vertical coordinate is the fraction of targets in that bin that were printed rests. A point below the diagonal means the model assigned rests more probability than their observed frequency in that bin. A point above it means the opposite.

More than half of the 614 targets fell in the lowest bin under each input. With pitch, the mean forecast in that bin was 4.6%, and 8 of 332 targets were rests (2.4%). With rhythm alone, the mean was 4.8%, and 9 of 333 were rests (2.7%). The gap was larger in some middle bins. For example, with pitch, targets in the 30–40% bin had a mean forecast of 34.6%, but only 7 of 40 were rests (17.5%). At the high end, the 80–90% bin contained 26 rests among 27 targets with pitch and 25 among 27 with rhythm alone. The score therefore shows that high and low forecasts distinguish many rests from note onsets, while the assigned percentages can differ from the observed frequencies.

Both inputs show this broad pattern. Some bins are small: the 70–80% bin contains six targets for each input, so one outcome shifts its observed rate by nearly 17 percentage points. Targets also share overlapping score prefixes. Figure 2 describes where probabilities agreed with the outcomes in Le Sapin. The paired Brier comparison in Figure 1 addresses whether adding pitch reliably improved forecasting.

Coverage and execution

The completed log contains one record for each of the 3,696 scheduled requests. Of these, 3,678 yielded valid forecasts, 17 failed and one produced an invalid response. Both main conditions covered all 614 targets. Median latency was 3.68 s with pitch and 3.41 s without pitch. Logged uncached list-rate cost was $46.98 across the production run.

Can other model variants forecast the rests?

All seven variants received the same prompts for 24 upper-voice targets, divided equally between rests and note or chord onsets. Each variant made three forecasts per target in each input condition. The constant forecast assigns a rest probability of 0.5 and has a Brier score of 0.25.

Five variants from three providers scored below 0.25 in both conditions. For GPT-6 Astra and Claude Opus 5.5, the 95% target-bootstrap intervals also fell below 0.25 in both conditions. GPT-6 Luna and Claude Haiku 5.5 scored above the baseline in both conditions. The shared panel shows that the result extends across providers and varies across models.

5. Discussion

Ampersand improved on reference forecasts across the three voices. It still missed about one in three printed rests at the 0.5 threshold. That gap matters for the proposed use of forecasts to find passages worth examining. A model can improve its probability estimates across the score while overlooking individual rests.

The small overall advantage for rhythm-only input came from the unbarred passage, where only 12 of 259 targets were rests. Across the piece, removing pitch lowered loss on notes and chords (0.04024 versus 0.04694) and raised loss on rests (0.27133 versus 0.25844). The whole-score interval includes zero. These errors show how the aggregate advantage arose, while the experiment leaves the musical reason for the difference open.

The fermata comparison illustrates a different limit. Showing the cue lowered the predicted rest probability at span 53 in both input conditions. At span 55, the direction depended on the input. Those forecasts show how Ampersand used the notation in two passages. Understanding how listeners hear these pauses would require evidence about listener responses or performance.

The study supplies target onsets and uses editorial voice assignments in one piece. Overlapping prefixes make nearby targets dependent, and familiarity with the score could influence forecasts even with the title and composer omitted. The findings support within-score claims about forecasting printed rests. The broader question of whether such forecasts can assist musical interpretation calls for evaluation across unfamiliar pieces and against human judgments.

Replication details

The shared-target comparison used its own single-voice transcription and target manifest. Draw 12 eligible upper-voice rests without replacement using seed 20261111. Process them in score order and match each to a distinct note or chord. Minimize mismatches lexicographically by beat, previous event type and distance to the nearest boundary. Break equal matches with the same seeded generator. The single-voice input has no voice column, and its duration field is dur. The full-score case study instead enumerates eligible targets in all three voices and treats free span 40 separately for timing-based analyses.

Use three fresh requests per target and condition with seed 20261111 for the request schedule. Run one request at a time per model with low reasoning. The API identifiers were ampersand-v0.1, gpt-6-luna, gpt-6.1-sol and gpt-6-astra. The Claude requests used the same prompts and specified claude-opus-5-5, claude-sonnet-5-5 and claude-haiku-5-5 through Anthropic’s Messages API. Claude used adaptive thinking with low effort. GPT and Claude had a 4,096-token output cap. Ampersand used streaming with context compaction disabled. Log model IDs, prompt hashes, repeat indices, response status, latency, tokens and cost. The analysis checked production request IDs and prompt hashes against the archived schedule.

The bootstrap used 10,000 draws with seed 20261111. The shared-target comparison resampled targets. The full-score pitch comparison resampled consecutive four-span blocks. Exact re-scoring requires the frozen target manifest and archived responses.
