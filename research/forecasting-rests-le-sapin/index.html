Symbolic music prediction

Forecasting notated rests in Sibelius’s Le Sapin

A single-score study with a shared-target model comparison · 14 November 2026

TaskDatasetEvaluationResultsDiscussionReferences

Abstract

Can a language model anticipate a printed rest when given the preceding score and the location of the next event? We tested Ampersand v0.1, a general-purpose language model from Humans&, on a three-voice transcription of Sibelius’s Le Sapin. Its forecasts improved on simple score-derived baselines. Adding written pitch did not reliably improve forecasts, and the small aggregate advantage of rhythm-only input came from the unbarred passage. Showing the barline fermata reduced the predicted rest probability at one closing target under both inputs. At the other target, the direction depended on the input. In a separate single-voice comparison on shared targets, Ampersand and two GPT variants beat a constant-probability baseline, while another GPT variant fell short. These findings describe forecasts of printed rests in one piece with the target onset supplied.

1. Task and relation to prior work

Janssen, Collins and Ren studied musical prediction by providing a preceding excerpt, or prime, and evaluating generated continuations or choices among candidate continuations. Their MIREX framework covers symbolic and audio representations. Our experiment adopts the prime–continuation setup and restricts the response to one probability for a binary event label. The voice and exact onset are provided. The evaluation therefore measures event-type forecasting conditional on location. [1]

The main question is whether a language model can forecast notated rests better than simple score-derived references. The earlier shared-target experiment tests whether that result extends to other model variants under the same setup. The full-score experiment also tests whether supplying pitch changes Ampersand’s forecasts. A separate ablation examines whether two closing predictions are sensitive to the preceding barline fermata. These comparisons address different claims. Beating a baseline establishes forecast skill relative to that reference, while the ablations measure the effect of changing the information in the prompt.

2. Dataset and representation

From engraved score to event table

The label source was the 1922 Wilhelm Hansen engraving edited and revised by Julia A. Burt, on Sibley PDF pages 41–43. We used Audiveris to convert the scan to MusicXML and compared it with a separately supplied MuseScore MusicXML export. When the files disagreed, the engraved symbols determined the labels. [2]

  1. Read the notation and recover timing. Unpack the compressed MusicXML and read its score in measure order. Convert each duration from divisions to quarter-note units using the current divisions value. Advance the cursor for ordinary events, retain the preceding onset for a chord member, and apply <backup> and <forward> to recover position across voices. Use exact rational values throughout. A forward move can create a gap but supplies no rest label.
  2. Reconcile symbols with the print. Exclude hidden rest elements and notes with invisible noteheads from the label candidates while retaining their effect on the XML cursor. Map notation lanes to independently moving or sustained upper, inner and bass lines. Preserve the moving voice when a beam crosses staves. Check the position and duration of each printed rest. For example, the supplied file merges each opening quarter-and-eighth-rest pair in spans 53 and 54 into one dotted rest. The transcription retains both printed symbols. It also uses the printed tuplet reading and span boundaries in the free passages.
  3. Validate and version the tables. Check every printed rest and all seven fermata locations against the score. Spot-check note pitches and durations, including reconciled notes. Check for duplicate event identities, overlaps within a voice and broken tie links. Use the score as the validation evidence. Store event-attached marks with the event and the three barline fermata locations in a separate table. Verify the hashes of both tables before assembling prompts.

A span is a numbered score segment. Most spans are 3/4 measures. The opening and the unbarred Risoluto are free spans with positions expressed as quarter-note offsets. Notes or chords beginning together in one voice form one onset. An explicitly printed rest is a separate event in its own voice, including when another voice sounds. An unnotated gap produces no event. Cross-staff figures retain their voice assignment. Tied continuations remain in the history as printed segments and contribute no new prediction target.

3. Evaluation design

Inputs and controls

For target i, use its (span, rational beat, voice) as the identifier. Sort the event history by span and beat and retain rows whose onset is strictly earlier than the target onset. This cutoff withholds every simultaneous event, including events in the other voices. A barline fermata printed before that onset may appear as a separate BOUNDARY row with voice score and blank pitch and duration. At the closing targets, the masked prompt removes that row alone. The title and composer are omitted.

The CSV record uses bar,beat,voice,type,pitch,duration,marks. The bar field carries the span ID, and type distinguishes NOTE, REST and BOUNDARY. The last line supplies the target’s voice, span and beat and asks for a single JSON probability. The opening supplies context only. Tied continuations retain their written segment durations in the prefix so the prompt does not expose the length of a later continuation.

Pitch
Written note name, accidental and octave, such as F♯4. A chord lists the pitches that begin together in one voice. Rest rows have no pitch.
Rhythm
Written onset and duration in quarter-note units. Beat 1 is the start of a span. A duration of ½ is an eighth note or rest. The rhythm-only prompt also retains the key signature, voice labels, earlier note/rest labels and score markings.
Voice and target
A voice is a notated musical line. The target is one withheld event at a supplied voice, span and beat.
Fermata and ablation
A fermata marks a hold or pause. Here the cue is at the barline. An ablation removes a specified input field or cue and measures how forecasts change.
Baseline and Brier score
A baseline is a reference forecasting rule. Brier score measures squared probability error on a scale from 0 to 1, with lower values indicating better forecasts.

The pitch-plus-rhythm and rhythm-only prompts differ by the removal of pitch values. Both retain the key signature, rhythm, voice labels and available markings. For spans 53 and 55, an additional prompt removes only the immediately preceding boundary fermata. These marks precede the quarter rest in span 53 and the whole-measure rest in span 55.

The requested and returned model identifier was ampersand-v0.1 for successful responses, with low reasoning. The protocol scheduled three fresh requests per target and condition in seeded shuffled order. The 3,696 production requests comprise 3,684 main forecasts and 12 masked-cue forecasts.

Response parsing and scoring

Collect the final assistant text from the provider response. Find its first opening brace and decode one JSON object starting there, which also accepts a JSON object inside a Markdown code fence. Read p_rest and accept only a JSON integer or floating-point number between 0 and 1 inclusive. A missing object, decode failure, missing field, string, Boolean or out-of-range value yields no scored forecast. Keep API failures and invalid responses in the request counts. As a sensitivity check, replace unavailable forecasts with 0.5 on the scheduled set.

If yi is 1 for a rest and 0 for a note or chord, and pir is the forecast in valid repeat r, each target contributes the mean of its squared probability errors. The reported Brier score averages those target losses. [3]

Brier = (1 / N) ∑i (1 / Ri) ∑r (pir − yi)²

References include a constant 0.5 probability, the rest prevalence outside the target span, and two metered-only rules based on beat position and the preceding span. The beat-position rule is voice-specific and uses Beta(1,1) smoothing. The previous-span rule checks for a same-voice event at the same beat and returns 0.9 for a rest, 0.1 for a note or chord and 0.5 if the reference event is unavailable. A descriptive balanced panel contains 12 rests and 12 unique same-voice notes matched by beat, previous event type and distance to a barline.

Because notes and chords outnumber rests in the full score, we report class-specific recall and distinguish the metered and free passages. The pitch effect subtracts pitch-plus-rhythm loss from rhythm-only loss on common valid repeat indices. Positive values favor adding pitch. The whole-score and metered intervals use 10,000 resamples of consecutive four-span blocks. The intervals characterize sensitivity within the piece, whose targets share much of their context. The two fermata cases are summarized individually.

Class-specific performance

At a threshold of 0.5 on each target’s mean forecast, accuracy was 559/614 with pitch and 560/614 without pitch. Rest recall was 73/109 and 72/109, while note or chord recall was 486/505 and 488/505. An always-note classifier gives 505/614 correct. Scoring the mean probability across repeats gave ensemble Brier scores of 0.07020 and 0.06835. Exploratory ROC-AUC was 0.923 and 0.924.

Coverage and execution

The completed log contains one record for each of the 3,696 scheduled requests. Of these, 3,678 yielded valid forecasts, 17 failed and one produced an invalid response. Both main conditions covered all 614 targets. Substituting 0.5 for unavailable forecasts in the sensitivity analysis yielded Brier scores of 0.08540 and 0.08211. Median latency was 3.68 s with pitch and 3.41 s without pitch. Logged uncached list-rate cost was $46.98 across the production run.

Can other model variants forecast the rests?

The earlier single-voice experiment used 24 shared targets, balanced between 12 rests and 12 note or chord onsets. Each model made three forecasts per target and input condition. GPT-6.1 Sol and GPT-6 Astra beat the constant 0.5 reference (Brier 0.25) in both conditions, as did Ampersand v0.1. GPT-6 Luna scored above 0.25 in both. Three of the four tested variants therefore showed forecast skill relative to this reference on the same targets. The sample spans two providers and one score, so the comparison establishes an observed result for these variants and this setup.

5. Discussion

Ampersand improved on the reference forecasts, although its errors were asymmetrical. The model missed roughly one in three printed rests at the operating threshold. Rhythm-only prompts reduced loss on note and chord targets while increasing it on rest targets. The free passage has a much lower rest prevalence than the metered spans and accounts for the rhythm-only advantage in the aggregate. In the paired results, rhythm only reduced Brier loss by 0.00844 within the free passage, which supplies 42% of targets and has only 12 rests. The metered comparison was nearly flat and slightly favored pitch. Across the whole score, rhythm-only forecasts had lower loss on notes and chords (0.04024 vs 0.04694) and higher loss on rests (0.27133 vs 0.25844). This explains the aggregate direction. The interval includes zero, and the experiment cannot establish whether pitch values distracted the model or whether the observed difference arose from forecast variability.

Showing the boundary cue lowered mean rest probability in both conditions at span 53. For pitch-plus-rhythm, the cue-visible forecasts there ranged from 10% to 95%. At span 55 the direction changed with the input condition. These observations concern how the model used a printed boundary symbol in two contexts. The study includes no measures of listener expectation or performed timing.

The target onset is supplied, the transcription depends on editorial voice assignments, and the sample consists of one piece and one model. Overlapping prefixes introduce dependence, and the same piece supplies the descriptive references. Omitting identification from the prompt leaves prior familiarity with the score possible. The full-score experiment establishes that Ampersand improves on simple forecasting rules in this piece. The shared-target comparison extends that finding to two GPT variants under the earlier single-voice setup, while Luna’s result shows that it does not hold for every variant tested. The ablations provide no clear whole-score benefit from pitch and show cue sensitivity at the two closing rests. Testing unfamiliar scores and further model families would establish how broadly these findings apply.

Replication details

The four-model comparison used its own single-voice transcription and target manifest. Draw 12 eligible upper-voice rests without replacement using seed 20261111. Process them in score order and match each to a distinct note or chord. Minimize mismatches lexicographically by beat, previous event type and distance to the nearest boundary. Break equal matches with the same seeded generator. The single-voice input has no voice column, and its duration field is dur. The full-score case study instead enumerates eligible targets in all three voices and treats free span 40 separately for timing-based analyses.

Use three fresh requests per target and condition with seed 20261111 for the request schedule. Run one request at a time per model with low reasoning. The API identifiers were ampersand-v0.1, gpt-6-luna, gpt-6.1-sol and gpt-6-astra. GPT requests used a 4,096-token output cap. Ampersand used streaming with context compaction disabled. Log model IDs, prompt hashes, repeat indices, response status, latency, tokens and cost. The analysis checked production request IDs and prompt hashes against the archived schedule.

Use the target as the unit of analysis. For a paired pitch estimate, average losses only over repeat indices with a valid response in both conditions. Use 10,000 bootstrap draws with seed 20261111, resampling targets in the four-model comparison and four-span blocks for the full-score pitch interval. Exact re-scoring requires the frozen target manifest and archived responses.
