Continual Learning: Benchmarks, Metrics, and Research Lines

Continual learning asks for a model that can learn from a sequence of changing data distributions while still performing well on what came before. This sounds close to ordinary fine-tuning, but the constraint is sharper: old data may be unavailable, future tasks are unknown, and the final model is judged on the whole history rather than only the newest task.

Problem Setup

A continual learner receives tasks or experiences D(1), D(2), ..., D(t) in order. Each task has its own dataset D(t) = {(x_i, y_i)}, i = 1..N_t, with inputs in X(t) and labels in Y(t). At step t, the algorithm uses only D(t) to update the previous model f(t-1) into f(t).

The goal is that f(t) handles all tasks seen so far: for any input x in X(1) ∪ ... ∪ X(t), it should output a label ŷ in Y(1) ∪ ... ∪ Y(t). The word "continual" therefore has two parts: the data are sequential, and evaluation is cumulative.

The standard failure mode is catastrophic forgetting: gradient updates that help the new task overwrite parameters useful for old tasks. The deeper tension is the stability-plasticity dilemma. A model that is too stable cannot learn the new distribution; a model that is too plastic forgets the past.

Formal Scenarios

The three standard scenarios differ in how the label spaces Y(t) and input spaces X(t) relate, and in what the model is told at test time:

  • Task-incremental learning (TIL). The task ID t_x of each test input is known. The problem reduces to mapping x in X(t_x) to ŷ in Y(t_x), so the model only chooses among that task's labels. This is usually the easiest protocol.
  • Domain-incremental learning (DIL). The label space stays the same, Y(1) = ... = Y(t), but the input distributions X(1), ..., X(t) differ: new lighting, style, sensor, geography, time period, or user population.
  • Class-incremental learning (CIL). The label sets are disjoint, for example Y1 = {C1, ..., C_k1} and Y2 = {C_k1+1, ..., C_k2}. No task ID is given at test time, so the model must classify among all classes seen so far.
  • Task-free or online continual learning. Task boundaries are unknown, or examples arrive in a stream with a small number of passes. This is closer to deployment, but harder to compare cleanly across papers.

Why CIL Is Harder Than TIL

The word "all" matters here. A common misconception about CIL is that training on task t only requires separating the classes in Y(t). In fact, the model must separate Y(1) ∪ ... ∪ Y(t), which is the difference between a multi-head model (one head per task, task ID given) and a single-head model. The classification problem grows with every task, and the current task's data contain no old-class negatives. CIL is therefore considerably harder than TIL.

Protocol Notes

  • The learner never knows how many tasks will arrive. Benchmarks fix a total of T tasks, t = 1, ..., T, mainly so metrics can be computed, but algorithms must not use T at any point.
  • In CIL, the first task should contain at least two classes. Later tasks have no size restriction.

Where Continual Learning Fits

Continual learning is easiest to understand next to its neighbors. In standard supervised learning, one task and one distribution are used for both training and testing. In multi-task learning, several tasks are trained together, and the model is tested on all of them. All task data are available at once.

Transfer learning and domain adaptation train on a source and care mainly about a target. They do not require the source to stay good. Meta learning trains across many tasks so that the learner can adapt quickly to a new one.

Online learning sees a stream of examples, but from a single fixed distribution. Continual learning also uses a stream, but the distribution changes over time (D1, ..., Dt). The learner must adapt to the new data without losing performance on earlier ones. That is the source of the forgetting problem described above.

Common Benchmarks

Benchmarks are not neutral: a method that shines on task-incremental Split MNIST may fail on class-incremental CIFAR-100. Good reports state the protocol, memory budget, task order, number of seeds, whether task identity is used at test time, and whether pretrained features are frozen or updated.

Benchmark family What it tests Useful caveat
Split, Permuted, and Rotated MNIST Basic task/domain/class-incremental behavior. Good for sanity checks, too small for claims about modern models.
Split CIFAR-10/100, TinyImageNet, ImageNet-R Standard class-incremental vision protocols. Results depend strongly on class order, augmentation, and memory size.
CORe50 Continuous object recognition with video-like object streams. More realistic than class splits, especially for robotics-style input.
CLEAR-10/100 Temporal visual drift in internet imagery from 2004 to 2014. Useful when the distribution shift is time rather than a hand-made task split.
DomainNet, PACS, OfficeHome-style streams Domain shift with shared or overlapping label spaces. Often closer to adaptation than class-incremental learning.
Continual World, Atari or Procgen task streams Continual reinforcement learning and policy adaptation. Forgetting can occur in representations, value heads, reward models, and policies differently.
TRACE, SuperNI-style task streams, continual pretraining corpora Large language model task learning, knowledge update, and retention. Need to separate parametric learning from retrieval, prompt memory, and benchmark contamination.

Metrics

Most metrics come from the accuracy matrix. Let A[i,j] be performance on task j after training through task i. The lower triangle of this matrix shows how each old task changes as the stream progresses.

  • Final average accuracy: ACC = (1/T) sum_j A[T,j]. This is the most common single-number result, but it hides how the model got there.
  • Forgetting: F_j = max_i<T A[i,j] - A[T,j], averaged across old tasks. This asks how much each task fell from its best historical performance.
  • Backward transfer: BWT = avg_j<T (A[T,j] - A[j,j]). Negative BWT is forgetting; positive BWT means later learning improved earlier tasks.
  • Forward transfer: compare performance on a new task before or during learning with a reference model trained only on that task. Definitions vary, so the baseline must be named.
  • Plasticity or learning accuracy: how well the model learns the current task compared with a single-task or joint-training reference.
  • Resource metrics: memory buffer size, added parameters, training FLOPs, wall-clock time, inference latency, and number of passes over data.

For language models, accuracy is not enough. Continual pretraining papers usually track validation loss or perplexity on old and new corpora, downstream benchmark retention, safety/alignment retention, and sometimes exact knowledge-update success. For agents, one must ask whether memory sits in weights, a retrieval database, an episodic log, or a test-time state.

Method Families

A useful taxonomy asks where the old knowledge is protected: data, logits, gradients, parameters, architecture, prompts, or external memory.

Family Core idea Examples Best fit
Replay Mix current data with stored or generated old examples. Experience replay, iCaRL, DER, GDumb, generative replay. Often strongest for class-incremental learning when memory is allowed.
Regularization Penalize changes to parameters or functions important for old tasks. EWC, Synaptic Intelligence, MAS, LwF distillation. Useful when storage is restricted; weaker when old class boundaries must be reconstructed.
Gradient constraint or editing Modify the update so the new gradient does not increase old-task loss. GEM, A-GEM, OGD-style orthogonal projection. A principled bridge between replay and optimization, but can be expensive.
Architecture or parameter isolation Allocate different subnetworks, masks, modules, or adapters to different tasks. Progressive Nets, PackNet, HAT, adapters, LoRA branches, MoE routing. Good when task identity or routing is available; watch parameter growth.
Prompt and representation methods Freeze a pretrained backbone and learn small prompt or projection modules. L2P, DualPrompt, CODA-Prompt, RanPAC. Modern vision CL with strong pretrained models and limited update budgets.
Continual pretraining schedules Resume large-model training with replay and learning-rate re-warming/re-decay. LLM continual pretraining with replay mixtures. Large language models where full retraining is too costly.
External memory and retrieval Store experience outside model weights and retrieve it at inference time. RAG, agent memory stores, semantic caches, episodic logs. Practical systems, but not always "learning" in the classical parameter-update sense.
Test-time learning and neural memory Let a hidden state or memory module update during inference. TTT layers, Titans, HOPE-style nested memory. Emerging sequence-model research; promising but not yet settled as standard CL.

Recent Research Lines

1. Replay Is Still Hard to Beat

Replay remains the practical baseline because it directly restores old-task input coverage. iCaRL combines exemplars with class means for class-incremental recognition; DER adds distillation on stored logits, preserving not only labels but the model's former function. The weakness is obvious: replay costs memory, can violate privacy constraints, and forces papers to report results under fixed buffer budgets.

2. Regularization Helps, But It Is Not Magic

EWC estimates parameter importance, often through the Fisher information, and discourages updates to important weights. SI and MAS estimate importance differently; LwF uses distillation so the new model preserves old outputs without old images. These methods are elegant because they avoid raw-data storage, but they struggle when class boundaries require old examples, especially in class-incremental protocols.

3. Gradient Editing Makes Stability a Constraint

GEM stores a small episodic memory and projects the gradient so the update does not increase loss on previous tasks. A-GEM simplifies this by comparing against an averaged reference gradient. This family treats forgetting as an optimization constraint rather than only a memory problem. It is attractive when one wants mathematical clarity, but gradient projection becomes awkward at modern model scale.

4. Pretrained Models Change the Game

With strong pretrained vision or language backbones, continual learning often shifts from "protect all weights" to "learn the right small handle." Prompt-based methods such as L2P, DualPrompt, and CODA-Prompt freeze most of the backbone and learn task-relevant prompts. RanPAC goes further toward simple representation geometry by combining pretrained features with random projections and prototype-like classifiers. This line belongs to parameter-efficient, representation- and architecture-based CL.

5. LLM Continual Learning Is Mostly About Scale and Interfaces

For large language models, naive full fine-tuning is expensive and can damage old capabilities. Current lines include continual pretraining with replay mixtures and careful learning-rate schedules, continual instruction tuning, PEFT modules such as LoRA/adapters, model editing for localized knowledge changes, and retrieval or agent memory. These are not interchangeable: RAG changes the context, PEFT changes a small parameter subset, editing changes localized associations, and continual pretraining changes the base distribution.

6. Memory-Layer Models Blur the Boundary

A newer direction asks whether the model can carry trainable memory inside the architecture. TTT layers update hidden-state models at test time; Titans adds a neural long-term memory module; nested-learning or HOPE-style proposals treat parts of the model as smaller optimization systems with different time-scales. These ideas connect continual learning, long-context modeling, fast weights, and agent memory. I would classify them as test-time learning or internal memory, adjacent to but not identical with classical supervised CL benchmarks.

7. Continual RL Is Its Own Problem

Reinforcement learning adds non-stationarity from the policy itself. A world model, value function, reward model, and actor can forget at different rates. Replay and regularization help, but the metric should include retained behavior, sample efficiency on new tasks, safety under distribution shift, and whether the agent can reuse skills rather than merely preserve classifiers.

How I Read the Field

The most honest way to compare continual learning methods is to ask four questions. First: what information is available at test time? Second: where is memory stored? Third: how much compute and parameter growth are allowed? Fourth: does the method improve the current task, preserve old tasks, or actually transfer between them?

My current view is that replay plus good representation learning is still the strongest classical recipe, while foundation-model CL is moving toward small adaptive interfaces: prompts, adapters, retrieval stores, and memory modules. The open question is whether these interfaces can become genuine learning rather than careful caching.
